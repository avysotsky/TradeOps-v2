## Защита рабочей среды

Для PostgreSQL использован существующий образ `postgres:17.11-bookworm`, отдельная
внутренняя Docker-сеть и уникальный временный контейнер с меткой принадлежности запуску.
Ограничения контейнера: 384 MiB RAM, 0.5 CPU, 128 процессов,
256 MiB временных данных. Опубликованных портов и постоянных томов нет.
Тестовый процесс ограничен одним CPU и последовательным запуском коллекций.
Администраторская роль использовалась только в одноразовом тестовом PostgreSQL,
где fixture создаёт и удаляет собственные уникальные базы.

Resource Guard — PASS до и после запусков.
Очистка проверяет уникальную метку и удаляет только ресурсы текущего запуска.
Постоянный PostgreSQL, его базы, backup, WSL-конфигурация и Comments Service
не изменялись. Снимки Docker до/после первого запуска: те же шесть контейнеров,
те же идентификаторы, состояния и health.

`.github` в результате интеграции совпадает с `origin/main`.
Десять дополнительных исторических workflow из F1-цепочки не перенесены.
GitHub Actions, очереди и старые orchestration runners не запускались.

Пользовательский незакоммиченный `src/TradeOps.Api/Properties/launchSettings.json`
сохранён без изменения; SHA-256 проверен по локальной резервной копии.
Работающий ранее терминал не перезапускался.
В конфигурации Terminal API оба execution switches остаются `false`.
Реальных placement/cancel/replace и мутирующих testnet-вызовов не выполнялось.
