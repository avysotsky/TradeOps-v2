## Изменение

Добавлен отдельный acceptance executable с реальным coordinator → scoped owner →
PostgreSQL capture store. Windows launcher с `-WithIsolatedInbox` использует сохранённый
DPAPI profile и передаёт короткоживущие credentials только через stdin в WSL. Оба
execution switches остаются false. Произвольного DB target в input нет.

Переиспользована исходная guarded fixture с отдельным compile-time namespace,
теми же schema resources/fingerprint, template и server-wide lease. Создаются только
marked clone и generated restricted role; перед socket проверяются права и capture
ownership. Source-sensitive failure детали не попадают в tool/PG logs: logging
настраивается только для setup session и удаляемой роли, не глобально.

Реальные события сохраняются как факты/observations, без legacy Orders/Fills.
Результат сверяет SQL row counts с actual capture returns и normalized events.
Неопределённые результаты при guard/cleanup failure не подменяются нулями.
Роль/источник/lease и clone очищаются в конце; runner отдельно проверяет остатки,
соседние контейнеры и Resource Guard. Production hierarchy/binding не создаётся.
