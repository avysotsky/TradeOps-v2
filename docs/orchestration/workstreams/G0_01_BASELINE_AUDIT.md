## 3. Concrete defects, failure modes and safety boundaries

### B0 — Release-blocking (execution / truth / custody)

**B0.1 — Global identity collision across venues/accounts (B1 owner).** Current [OrderConfiguration unique `ClientOrderId`](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Infrastructure/Persistence/Configurations/OrderConfiguration.cs#L15-L20) and [FillConfiguration unique `ExchangeFillId`](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Infrastructure/Persistence/Configurations/FillConfiguration.cs#L18-L25) are globally keyed. Order/Fill domain entities lack venue/account dimensions. Two venues can legitimately reuse external IDs. **Gate:** deterministic two-venue/two-account collision fixture, durable composite uniqueness and all read/update/event routes account-fenced; migration assessed before shipping.

**B0.2 — Dispatch is not durable exactly-once-intent (B2 owner).** [OrderManager lines 79–148](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Application/Services/OrderManager.cs#L79-L148) saves `Submitted`, alerts, then sends to venue. There is no durable `pending/sending/unknown` command/attempt/outbox/fencing transaction in this path. Timeout catch attempts a lookup, but a crash, cancellation, HTTP exception or failed lookup can leave ambiguous state. **Gate:** crash at every dispatch cut point; restart must never blindly resend; authoritative fills and order recovered before intent is terminal.

**B0.3 — Reconciliation not snapshot-complete (B4 owner).** [OrderReconciliationService lines 26–73](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Application/Services/OrderReconciliationService.cs#L26-L73) looks up local candidates individually, with no completeness marker/barrier for all orders/fills/positions. A missing order correctly becomes `Unknown`, but cannot be interpreted as resolved cancellation. [ExchangeEventProcessor lines 107–128](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Application/Services/ExchangeEventProcessor.cs#L107-L128) logs and drops fills for unknown local orders. **Gate:** gap/duplicate/out-of-order/partial pagination fixtures, durable orphan ingress, monotonic recovery and no false zero or status regression.

**B0.4 — Non-atomic / bypassable risk verdict (B5 owner).** [RiskEngine](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Application/Services/RiskEngine.cs#L13-L110) runs before order mutation with no demonstrated atomic synchronization of kill switch/fencing/aggregate exposure at send. The standalone TerminalApi has separate, gated [manual mutation endpoints](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/apps/TradeOps.TerminalApi/Controllers/DeribitTerminalController.cs#L209-L321), **outside the core OMS**. **Gate:** no risk-increasing send after kill switch, under concurrency, failure/reconnect and across all entry points.

**B0.5 — IBKR invalid `orders` shape becomes empty list (IBKR/B4 owner).** [`IbkrPaperExchangeClient.GetOrderSnapshotAsync` lines 260–276](https://github.com/avysotsky/TradeOps-v2/blob/c7a0d29028d7cf4958a26aa4879b99b3e39f7b14/src/TradeOps.Infrastructure/Exchange/Ibkr/IbkrPaperExchangeClient.cs#L260-L276) returns `Array.Empty<Order>()` if `orders` missing/not an array. This conflates a malformed/unavailable API shape with **authoritative zero orders**, even though order sending is disabled for IBKR. **Gate:** explicit `Unavailable/Incomplete` plus source/time/pagination evidence, tests that invalid shape never means zero or authorizes reconciliation.

### B1 — Pre-integration blockers (read-only data, CI, branch management)

**B1.1 — Private Deribit REST snapshots are transitional (B3/B4/F1 owner).** [#55](https://github.com/avysotsky/TradeOps-v2/pull/55) adds `loading/ready/unavailable`, UTC sample markers, epoch/AbortController and 8-second bounded polls. This is useful fail-closed UI safety, but [`isAccount` checks mainly currency, `isOrder` accepts null keys](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/apps/trade-terminal/src/Terminal.tsx#L151-L169), while [TerminalApi account mapping returns nullable numeric values](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/apps/TradeOps.TerminalApi/Controllers/DeribitTerminalController.cs#L126-L199). A structurally accepted, semantically incomplete snapshot can look ready. **Gate:** typed required financial/order fields, per-section completeness, source time, stale/partial explicit state, zero-vs-unavailable tests; authoritative durable WS ingress later.

**B1.2 — Mainnet readonly is *flag and launcher controlled*, not an OMS safety certificate (security/B3 owner).** [Defaults](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/apps/TradeOps.TerminalApi/appsettings.json#L2-L9) false/false; [server TradingEnabled guard](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/apps/TradeOps.TerminalApi/Controllers/DeribitTerminalController.cs#L29-L42) requires both switches on mainnet; launcher [pins Git SHA and decrypts Windows CurrentUser DPAPI vault only after builds/tests](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/scripts/deribit/Start-MainnetReactTerminalReadOnly.ps1#L32-L121); [forces flags false, clears exchange credentials before Vite](https://github.com/avysotsky/TradeOps-v2/blob/e4a067c9422845e9dd4579a36a728737f036185f/scripts/deribit/Start-MainnetReactTerminalReadOnly.ps1#L130-L177).
